# Ask for an App Store rating after the third finished session

## Goal

Collect App Store ratings from learners who already got value from the app. The owner approved the feature on 2026-11-09.

## Overview

### Context

- Ask with Apple's system sheet only (`AppStore.requestReview(in:)`, iOS 16+; `SKStoreReviewController.requestReview(in:)` on iOS 15). No custom "rate us" UI. Apple shows the sheet at most 3 times a year per user and may skip it silently.
- Trigger: the 3rd finished session after the results screen appeared. Never at first launch, never mid-session. At most one request per app version (`CFBundleShortVersionString`); a later version needs 3 new finished sessions.
- iOS app only. The web build (`app.bgtrainer.korchasa.dev`) never reaches the bridge.
- "Finished lesson" in the request = any session that reaches the results screen: a single game or a round (FR-GAME-SESSION, FR-ROUND). The app has no notion of finishing a whole textbook lesson. Aborted rounds and games left by Back reach no results screen and do not count.

### Current State

- Native bridge today: 4 official Capacitor plugins via SPM (`ios/App/CapApp-SPM/Package.swift`, generated by `cap sync`). No local plugin, no `CAPBridgeViewController` subclass; `Main.storyboard` instantiates `CAPBridgeViewController` directly.
- Persistence: `utils/storage.ts`; native reads come from a cache filled only for `TRACKED_KEYS`.
- Results screen shown by `App.tsx` `handleComplete` (`setScreen("results")`).

### Constraints

- No new npm or Swift package. A community plugin is not needed: a local plugin is ~40 lines of Swift.
- Do not bump `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION`.
- Logic testable outside Vite: the counter/threshold/version unit must not import `utils/platform.ts` or `utils/storage.ts` (AGENTS.md, "Scripts that evaluate the app's data").

### Bridge choice

- **Chosen: local Capacitor plugin in the App target.** `ios/App/App/StoreReviewPlugin.swift` (`CAPBridgedPlugin`, jsName `StoreReview`: `appVersion()`, `requestReview()`), registered by `ios/App/App/BridgeViewController.swift` (`CAPBridgeViewController` subclass, `capacitorDidLoad` → `registerPluginInstance`); `Main.storyboard` points at the subclass. JS side: `registerPlugin("StoreReview")` from `@capacitor/core`, already installed.
  - Pros: no dependency; same bridge the official plugins use; promise API with errors.
  - Cons: 4 hand-written `project.pbxproj` entries per Swift file (no synchronized groups at `objectVersion = 60`).
- **Rejected: `WKScriptMessageHandler`** — bypasses Capacitor's call/promise plumbing, needs its own reply channel for the version.
- **Rejected: community plugin (`@capacitor-community/in-app-review` and similar)** — a new dependency for two calls; the task forbids adding one when a local option works.
- **Rejected: `@capacitor/app` `getInfo()` for the version** — another dependency; the local plugin returns `CFBundleShortVersionString` itself.

## Findings

- Local `.env` (gitignored, never committed) sets `VITE_PLATFORM=ios`, so every local `deno task check` / `build` here compiles the *iOS* flavour under the name "web". CI has no `.env`, so the deployed web app is unaffected. To inspect a real web bundle locally, set `VITE_PLATFORM=web` explicitly.
- Capacitor Preferences writes reach `Library/Preferences/dev.korchasa.bgtrainer.plist` with a delay of seconds; read the plist after a pause, not right after the action.

## Solution

1. `reviewPrompt.ts`: `ReviewState { finished, askedVersion }`; `countFinished(state, version)` (+1 unless this version was already asked), `isReviewDue` (`finished >= 3` and version not asked), `markRequested` (`finished = 0`, `askedVersion = version`), `parseReviewState` (null → fresh, malformed → throw).
2. Mark the version only when the request is actually sent, so a results screen left before the delay keeps the request due for the next finished session.
3. `storeReview.ts`: `countFinishedSession(): Promise<boolean>` and `requestStoreReview()`; both return at once off iOS; bridge failures logged with `console.warn`, never thrown into the UI.
4. Swift: `AppStore.requestReview(in:)` on iOS 16+, `SKStoreReviewController.requestReview(in:)` on iOS 15, scene from `bridge.viewController.view.window.windowScene`.
5. Verify: `deno task test`, `deno task check`, Release simulator build, walk with screenshots, grep the web bundle.
